이 저장소에서 **실제로 사용자가 지적한 결함**들을 규칙으로 굳힌 것이다. 전부 같은 종류다 —
값을 각자 정해서 서로 어긋났고, 눈으로만 확인해서 못 잡았다.

## 언제 이 스킬을 쓰는가

- 요소가 서로 겹치거나 가려지는 문제를 고칠 때
- 나란히 놓인 컨트롤의 높이·기준선을 맞출 때
- 카드·목록의 열이 어긋나 보이는 것을 고칠 때
- 드롭다운·모달의 여닫기 동작을 만들 때
- 값이 없는 상태(사진 없음, 텍스트 없음)의 화면을 만들 때
- 화면 코드를 고치고 "됐다" 고 말하기 직전 — 5절의 확인 절차를 돌린다

## 언제 쓰지 않는가

- 화면 구조·영역 분할·디자인 토큰을 **처음 확정**할 때 → `curvez:wireframe-spec` 을 쓴다.
  이 스킬은 이미 있는 화면의 어긋남을 잡는다
- 색·서체·레이아웃의 **미감과 방향**을 정할 때 → `frontend-design` 을 쓴다.
  "예쁘게" 는 이 스킬의 일이 아니다. 이 스킬은 "맞게" 만 다룬다
- 컴포넌트·라우트를 **새로 구현**할 때 → `curvez:nextjs-implementation` 을 쓴다
- typecheck·lint·test·build 를 돌려 수치를 낼 때 → `curvez:quality-gate` 를 쓴다.
  이 스킬의 확인은 **브라우저에서 재는 것**이라 그 게이트가 잡지 못한다

**이유:** 여기 있는 결함은 전부 타입 검사·린트·테스트·빌드를 **통과한 채로** 사용자에게 갔다.
`z-10` 두 개가 부딪히는 것도, 36px 옆에 42px 이 서는 것도 문법 오류가 아니다.
그래서 별도의 확인 절차가 필요하고, 그 절차가 이 스킬이다.

## 절차

### 1. 지적받은 것을 먼저 잰다

고치기 전에 **숫자를 얻는다.** 짐작으로 원인을 정하지 않는다.

```js
// 브라우저에서 실행한다
[...document.querySelectorAll('<대상 선택자>')].map(el => {
  const r = el.getBoundingClientRect();
  const s = getComputedStyle(el);
  return { w: +r.width.toFixed(1), h: +r.height.toFixed(1),
           top: +r.top.toFixed(1), bottom: +r.bottom.toFixed(1), z: s.zIndex };
});
```

이 단계는 **수치가 나와야** 끝난다. "어긋나 보인다" 는 아직 시작도 안 한 것이다.

**이유:** 원인이 셋 이상인 경우가 실제로 있었다. 카드 열이 어긋난 건은 중첩 괄호 파싱 실패,
빈 줄 제거, `flex` 의 `min-width:auto` 세 가지가 겹쳐 있었다. 눈으로는 하나로 보인다.

### 2. 값을 각자 정하지 않는다 — 공유 자리에서 받는다

같은 성격의 값이 두 곳 이상에 나오면 그 자리를 만든다.

| 값 | 사는 곳 |
|---|---|
| 겹침 순서 | `src/app/globals.css` 의 `--layer-*` |
| 컨트롤 높이·기하 | `src/presentation/components/tds.ts` |
| 탐색 화면 URL | `src/presentation/lib/explore-href.ts` |

**새 숫자를 컴포넌트에 직접 쓰지 않는다.**
**이유:** 각자 정하면 우연히 같은 값이 되고, 같아지면 순서가 DOM 위치로 결정된다.
실제로 저장 칩과 지역 드롭다운이 둘 다 `z-10` 이라, 카드가 뒤에 있다는 이유만으로
칩이 드롭다운을 뚫고 나왔다. 같은 카드의 사진은 `z-auto` 라 드롭다운 아래로 깔려서
한 카드가 위아래로 찢어져 보였다.

### 3. 고친다

4절 규칙을 따른다.

### 4. 다시 재서 같아진 것을 확인한다

1단계와 같은 코드를 다시 돌려 **수치가 일치하는지** 본다.
헤더 컨트롤이라면 `h` 와 `top` 과 `bottom` 이 전부 같아야 한다.

### 5. 새로 띄운 서버에서 본다

```bash
lsof -ti :3100 | xargs -r kill
rm -rf .next && pnpm build && PORT=3100 pnpm start &
```

**돌고 있던 서버에서 확인하지 마라.**
**이유:** 이 저장소에서 두 번 당했다. `pnpm start` 로 띄운 프로세스를 남겨 둔 채 리빌드하면
서버가 낡은 청크와 새 청크를 섞어 내보낸다. 사용자가 "고쳐지지 않았다" 고 보고한 화면이
실은 중간 빌드였고, 그 사이 나는 멀쩡한 코드를 다시 고치고 있었다.
프로세스 이름은 `next start` 가 아니라 **`next-server`** 라 `pkill -f "next start"` 는 아무것도 못 잡는다.

## 규칙

### 겹침은 역할로 고른다

`globals.css` 의 `--layer-card-overlay`(10) / `--layer-bar`(20) / `--layer-popover`(30) 중에서 고르고
`z-[var(--layer-popover)]` 로 쓴다.

**숫자를 직접 쓰지 않는다.**
**이유:** 2절의 이유와 같다. 덧붙여, `position: relative` 에 `z-index: auto` 인 조상은
**스택 컨텍스트를 만들지 않는다.** 그래서 자식의 `z-10` 은 그 안에 갇히지 않고 문서 최상위에서
다른 `z-10` 과 직접 겨룬다. 이 사실을 모르면 부모에 `relative` 를 더해 "격리했다" 고 착각한다.

**여는 것은 항상 위다.** 사용자가 방금 연 것이 무언가에 가려지면 고장으로 읽힌다.

### 나란히 선 것은 높이를 공유 상수에서 받는다

헤더의 작은 컨트롤은 `CONTROL_SM` 을 쓴다. 아이콘만 있는 것도 글자가 있는 것도 같은 상수를 받는다.

`leading-none` 을 빼지 않는다.
**이유:** `line-height` 가 높이를 밀어 올려서, 아이콘만 있는 버튼과 글자가 있는 버튼이 달라진다.
실측으로 테마 토글 36px 옆에 언어 선택 42px 이 서 있었다. 6px 은 재야 알지만
**어긋나 보인다는 인상은 재지 않아도 남는다.**

### 여닫는 것은 바깥 클릭·Esc·**항목 선택**으로 닫힌다

`<details>` 로 만든 드롭다운에는 `data-dismissable` 을 붙인다.
`DismissOnOutside` 가 라우트 전체에서 한 번만 처리한다.

셋을 모두 확인한다 — 바깥 클릭, Esc, **안에서 항목을 고른 경우**.
**이유:** 고르면 목록이 다시 조회되는데 드롭다운이 덮고 있으면 바뀐 결과가 보이지 않는다.
"안쪽 클릭은 유지" 만 구현하면 이 경우가 빠진다. 실제로 그렇게 빠뜨렸다.

**드롭다운마다 리스너를 달지 않는다.**
**이유:** 화면에 있는 개수만큼 `document` 리스너가 생긴다. 지역 필터가 2단이 되면서
같은 화면에 셋이 됐다.

### 값이 비어도 자리를 지킨다

텍스트가 없으면 줄을 지우지 말고 같은 높이의 빈 자리를 남기고 `aria-hidden` 을 붙인다.

**이유:** 지우면 그 카드만 아래 요소가 위로 올라와 한 행의 단이 어긋난다.
비어 있는 것은 그 카드의 사정이지 격자의 사정이 아니다.

### 사진이 없으면 없다고 말한다

`NoImage` 를 쓴다. 빈 색면을 깔지 않는다.

**이유:** 색면은 "아직 안 떴다" 와 "없다" 를 구분해 주지 않아 기다리게 만든다.
브라우저 기본 깨진 이미지 아이콘은 더 나쁘다 — 앱이 고장 난 것으로 읽힌다.
URL 이 있는데 안 뜨는 경우까지 잡으려면 `onError` 만으로는 부족하다.
서버가 그린 `<img>` 는 하이드레이션 전에 로드를 끝내기도 하는데, 그때의 error 는
리스너가 붙기 전에 지나간다. `complete && naturalWidth === 0` 으로 되짚는다.

### 플렉스 아이템에는 `w-full` 과 `min-w-0` 을 함께 준다

**이유:** 플렉스 아이템의 기본 폭은 `max-content` 이고 기본 최소 폭은 `min-content` 다.
`w-full` 이 없으면 내용이 적은 카드만 열보다 좁아지고(실측 352px 열에 250px 카드),
`min-w-0` 이 없으면 `truncate` 한 긴 주소가 열을 밀어낸다(실측 485px).
두 방향으로 각각 깨지므로 둘 다 필요하다.

### 자동화 탭은 **화면에 보일 때만** 제대로 잰다

`computer:screenshot` 을 한 번 찍어 페인트를 강제한 **뒤에** 값을 읽는다.

**숨겨진 탭에서 잰 값을 믿지 마라.**
**이유:** 브라우저가 보이지 않는 탭의 일을 멈춘다. 이 저장소에서 세 번 당했다 —
`getBoundingClientRect` 가 전부 0 으로 나왔고, `IntersectionObserver` 콜백이 오지 않아
스크롤 연동이 "동작하지 않는다" 고 잘못 읽었고, 커스텀 프로퍼티를 바꾼 뒤
`getComputedStyle` 이 **한 단계 전 값**을 돌려줬다. `requestAnimationFrame` 은 아예
호출되지 않아 45초 타임아웃이 났다.

전부 코드가 아니라 환경 문제였고, 스크린샷을 한 장 끼우면 사라진다.

### 브라우저 콘솔은 추적을 켠 뒤 새로고침하고 읽는다

**"콘솔이 깨끗하다" 를 추적 시작 전에 로드된 페이지로 판정하지 마라.**
**이유:** 이 저장소에서 실제로 그렇게 잘못 보고했다. `read_console_messages` 는 처음 호출한
시점부터 기록하므로, 그 전에 난 경고는 애초에 잡히지 않는다. 사용자가 같은 경고를 다시 보고했다.

## 완료 기준

- [ ] 1단계와 4단계의 측정값을 둘 다 남겼고, 맞춰야 할 값이 실제로 같아졌다
- [ ] 새로 쓴 `z-index` 가 0개다 — 전부 `--layer-*` 를 참조한다
      (`grep -rn "z-[0-9]" src/` 가 0줄)
- [ ] 새로 쓴 컨트롤 높이가 0개다 — 공유 상수를 받는다
- [ ] 여닫는 것을 만들었다면 `data-dismissable` 이 붙어 있고, 넷을 확인했다 —
      바깥 클릭 → 닫힘 / 항목 선택 → 닫힘 / 링크 아닌 안쪽 클릭 → 유지 / Esc → 닫힘
- [ ] `.next` 를 지우고 새로 띄운 서버에서 봤다
- [ ] `pnpm typecheck && pnpm lint && pnpm test && pnpm build` 와
      `node scripts/check-architecture.mjs` 가 전부 통과한다
